## Current implementation

- `README.md`: setup, capabilities, interpretation and collection limits.
- `app/ui/main.py`: customtkinter desktop GUI; startup real scan, genuine file imports, background workers, progress/errors, evidence windows and local PDF export. Tabs are Footprint, Scan coverage, What they know, Inner circle, Findings and Fix first. The GUI currently expects `D:\NEXDATA`.
- `app/engine/records.py`: shared Record/Finding contract. Preserve evidence IDs and source references.
- `app/pipeline.py`: content-based parser dispatch; media processed last so OCR can use names from imported exports. Returns records, findings, coverage, summary, graph, errors and additive `sourceCoverage`.
- `app/engine/rules.py`: existing findings, summaries and graph. Device findings cover recent location access, tracker-domain contacts, laptop app-data stores and log pattern counts. Preserve existing findings unless an evidence-backed correction requires a deliberate change.
- `app/engine/coverage.py`: source-specific scanned/partial/unavailable/not-provided/not-assessed states, lower-bound display and missing-data handling. A finished job is not a whole-device audit.
- `scanner/scan.py`: stdlib laptop scanner and optional authorised Android ADB collection. App-folder metadata, bounded log regex counts and Recent shortcut count; no matched log values retained. Android package failures are counted as partial coverage.
- `app/parsers/chrome.py`: Chrome/Edge profile metadata through read-only queries. Selects history metadata, cookie names/domains, saved-login domains and supported permissions; does not select password/cookie values. Each database has its own coverage row. A malformed Preferences file no longer discards readable history/cookies. Cookie associations are indicators, not proof that session recording occurred.
- `scanner/browser_access.py`: Windows Restart Manager diagnosis and guarded browser-owner shutdown. Closing browser windows can leave background processes holding database locks. Normal shutdown is tried first; explicit consent permits stopping only verified windowless Chrome/Edge lock owners, with PID/start-time checks. Visible windows and PID reuse are refused. The user's past approval to stop background Chrome was for that operation, not standing permission to terminate future processes.
- `app/parsers/deviceScan.py`, `app/parsers/iosPrivacy.py`: laptop/Android scan JSON and iPhone App Privacy Report NDJSON. Bad NDJSON lines are skipped and reflected in partial coverage.
- `app/parsers/ocr.py`: RapidOCR/OpenCV recordings and screenshots; roughly one frame per second, duplicate-frame skip, fuzzy known-name snapping and supported Instagram friend activity/WhatsApp status layouts.
- `samples/make_recordings.py`, `samples/make_device.py`: deterministic synthetic fixtures; these do not describe the real user.

## Remaining work and suggested continuation

The user plans a Kivy mobile application later; that UI and mobile collection work are not implemented. Genuine account exports are still necessary for social relationships, interests and chat content.

Two OCR issues identified in the earlier investigation remain candidates for a focused fix:

1. `ocr.parse()` resets its record counter for each file and constructs IDs such as `oc-in-00001`. Two same-platform media inputs can therefore collide. Reproduce with two inputs and namespace IDs per source while preserving evidence references.
2. `ocr.frames()` compares a whole-screen 16x16 average hash and skips distances of six bits or less. A meaningful header-only change, such as the status-viewer heading, can be skipped. An earlier synthetic status screen needed a more visibly distinct fixture. Reproduce with a subtle but semantically changed screen and fix detection rather than weakening assertions or disguising the input.
